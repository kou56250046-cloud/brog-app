# PC でコードブロックだけを広げる

規模: S（`src/assets/style.css` のみ。データ構造・外部連携の変更なし）

## 背景

記事ページの本文列は `--measure: 44rem`（約 704px）固定で、コードブロックも同じ幅。
1 行に入るのは約 80 桁。PC の広い画面では右側と左右の外側が空いている。

公開記事のコード行を集計した結果（全角を 2 桁換算、2026-10-01 時点）:

| 言語 | 行数 | 80 桁超 | 100 桁超 | 120 桁超 |
|---|---|---|---|---|
| python | 3821 | 22% | 3% | 9 行（0.2%） |
| bash | 287 | 19% | 9% | 5% |

PC では折り返しが既定で OFF のため、python の 5 行に 1 行が横スクロールになっている。

本文の段落は日本語の読みやすさ（1 行 40 字前後）のため今の幅を保ち、コードブロックだけを広げる。

## 受入条件

W はビューポート幅を `window.innerWidth`（CSS px）で測った値とする。
「変更前と同じ」は、検証手順 1 で変更前に控えた値との差が 0 であることを指す。

- [ ] W ≥ 1200 の記事ページで、`.prose > .code-block` が本文列の左端から目次の手前までいっぱいに広がる
  - W = 1920 のとき、コードブロックの幅が 1080px 以上
  - W = 1366 のとき、コードブロックの幅が `W − 15（スクロールバー）− 48 − 304 − 20` 以上（= 979px 以上）
- [ ] 同じ条件で、`.prose` の直下にあるコードブロック以外の要素（段落・見出し・リスト・表・図・コールアウト・連載ナビ・「続きから読む」）の幅は変更前と同じ
- [ ] 目次は右側に残り、コードブロックと重ならない（コードブロックの右端 < 目次の左端）
- [ ] 次の要素の左端の x 座標が一致する: `.brand`、`.post-crumb`、`.prose`、`.post-foot` の最初の子要素
- [ ] W = 1199 / 1100 / 375 の記事ページでは、検証手順で測る値がすべて変更前と同じ
- [ ] トップページの `.home-grid` の幅と左端が、W = 1920 / 1366 で変更前と同じ
- [ ] W = 1920 で `2026-09-29-agent-parts-4-errors-logs`（python の最長行は 119 桁）を開くと、`.code-block[data-lang="python"] pre` がすべて `scrollWidth <= clientWidth` になる
- [ ] 同じく W = 1920 で `2026-09-29-ai-agent-data-design-1-structured`（最長行 134 桁）では、横スクロールが残るのは 120 桁を超える行を含むブロックだけになる

## 非目標

- 表（`.table-scroll`）・フロー図（`.figure`）・コールアウトは広げない
- リストやコールアウトの中にあるコードブロックは広げない（現在の原稿には 0 件）
- 本文の段落の幅（`--measure`）は変えない
- 120 桁を超える行（python 9 行、bash の 5%）は横スクロールのまま残す。器をさらに広げたり、フォントを小さくしたりはしない
- 記事以外のページ（トップ・一覧・タグ・404）のレイアウトは変えない。`--wrap` の全体の既定値も変えない
- コードのフォントサイズ・行間・ハイライトの配色は変えない
- 折り返しボタンの既定（640px 以下で ON、それ以外は OFF）と `app.js` は変えない
- `:has()` に未対応の古いブラウザでは今のレイアウトのまま残す。テンプレートに body クラスを足すなどの代替は入れない
- 印刷レイアウトは変えない

## 設計

`@media (min-width: 1200px)` の中で次を指定する。

```css
/* 記事ページだけ全体の器を広げる。ヘッダー・フッターも同じ変数を使うので左端が揃う */
body:has(.post) { --wrap: 1440px; }
.post-layout { grid-template-columns: minmax(0, 1fr) 240px; }
/* 本文は今の幅を保ち、コードブロックだけが列いっぱいに広がる */
.prose > :not(.code-block) { max-width: var(--measure); }
```

- 器の最大幅を 1440px にする。左右の余白 24px ずつ、目次 240px、間隔 64px を引くと、コード列は最大 1088px になる
- 広げる対象は言語を問わず、すべての `.code-block`（`text` の実行結果や `json` も含む）。言語ごとに幅を変えると、並んだブロックの右端がそろわなくなるため
- 1200px を境にする理由: これより狭い画面では今の 1180px の器がほぼ画面いっぱいなので、広げても数桁しか増えない
- `.post-head h1` / `.spec` / `.post-desc` / `.post-foot > *` は既存の `max-width` 指定があるので、器が広がっても幅は変わらない

## 検証方法

1. **変更前に**、`node build.mjs` → `node scripts/serve.mjs` で開き、claude-in-chrome で次の値を控える
   - 記事 `2026-09-29-agent-parts-4-errors-logs` を W = 1920 / 1366 / 1199 / 1100 / 375 で開き、各幅で次を記録する
     - `window.innerWidth`
     - `.prose` の直下にある各要素の種類ごとの `getBoundingClientRect()` の幅と左端（`p`・`h2`・`ul`・`.table-scroll`・`.figure`・`.callout`・`.code-block`・`.series`）
     - `.brand`・`.post-crumb`・`.prose`・`.post-foot` の最初の子要素の左端、`.toc` の左端
   - トップページの `.home-grid` の幅と左端（W = 1920 / 1366）
2. CSS を変更し、`node build.mjs` が成功することを確かめる
3. 手順 1 と同じ値を測り、受入条件と照らし合わせる。ウィンドウ幅を合わせられない場合は、`innerWidth` が一致する状態で比べる
4. 受入条件の python 2 記事で、`pre` の `scrollWidth` と `clientWidth` を測る
5. W = 1920 と 1366 のスクリーンショットを撮り、ユーザーに見せる
