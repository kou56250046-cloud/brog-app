# Dev Knowledge Base

AI・設計・開発ツールを、図とコードで基礎から発展まで解説するエンジニアの学習ノート。

**公開サイト:** https://kou56250046-cloud.github.io/brog-app/

Markdown で書いた記事を、npm 依存ゼロの自作ジェネレーターで静的 HTML にし、GitHub Pages で公開している。

---

## 記事の作り方（Claude Code へのお願いの仕方）

記事は Claude Code に頼んで作る。流れは次の 4 段階で、**構成案の段階で必ず一度止まる**。

```
1. お願いする       「〜について記事を作成して」
2. リサーチ         Web で最新情報・設計思想・批判的意見まで調べ、research/ にメモを残す
3. 構成案の提示     タイトル案 3 つ・章立て・入れる図/表/コード・分量  ← ここで止まる
4. 執筆と確認       承認後に執筆 → ビルド → コードの構文確認 → 表示確認
```

### 基本のお願い

```
〜について記事を作成して
```

これだけで動く。例:

```
RAG について記事を作成して
Python の非同期処理について記事を作成して
GitHub Actions のキャッシュについて記事を作成して
```

### 条件を付けたお願い

指定したいことがあれば一緒に書く。書かなければ既定値（Python・入門〜発展・1 本）で進む。

| 指定したいこと | 書き方の例 |
|---|---|
| 対象読者・レベル | 「入門者向けに」「実務経験者向けに発展だけ」 |
| 重点 | 「設計思想を中心に」「コードを多めに」「比較表を中心に」 |
| 範囲 | 「LangGraph に絞って」「セキュリティの話は除いて」 |
| 分量・分割 | 「短めに 5,000 字くらいで」「3 本の連載に分けて」 |
| 言語 | 「コードは TypeScript で」 |
| 元にする資料 | 「この URL の内容を踏まえて: https://…」 |

例:

```
MCP サーバーの作り方について、実践レベルでコード多めに記事を作成して
プロンプトキャッシュについて、仕組みの図を中心に短めの記事を作成して
LLM の評価（evals）について、3 本の連載に分けて記事を作成して
```

### 構成案が出たら

構成案を見て返事をする。直したい点はそのまま伝えればよい。

| 返事 | 意味 |
|---|---|
| 「案2で」「OK」 | そのタイトル・構成で執筆に進む |
| 「3 章と 4 章を入れ替えて」「〇〇の章を足して」 | 構成を直して再提示 |
| 「タイトルをもっと刺さる感じに」 | タイトル案を出し直す |

### 書いた後のお願い

| やりたいこと | お願いの例 |
|---|---|
| 公開する | 「コミットしてプッシュして」 |
| 手直し | 「〇〇の章をもっと具体的に」「このコードに説明を足して」 |
| 最新情報に更新 | 「〜の記事を最新情報で更新して」 |
| 下書きに戻す | 「〜の記事を非公開にして」（`status: draft` にする） |

`main` にプッシュすると GitHub Actions が自動でビルドして公開する（1〜2 分）。

## 自分で書く・直す場合

原稿は `content/articles/YYYY-MM-DD-<slug>.md`。書き方と記法（コードブロック・フロー図・コールアウト）は [`docs/writing-guide.md`](docs/writing-guide.md) にまとめてある。

最小の原稿:

```markdown
---
title: 記事のタイトル
description: 一覧と検索に出る 1〜2 文
date: "2026-10-01"
category: AIエージェント
tags: [LLM, Python]
level: [basic, practice]
status: published
---

本文…
```

カテゴリーを増やすときは `site.config.mjs` の `categories` に追加する。

## コマンド

Node.js 20 以上があれば動く。`npm install` は不要。

```bash
node build.mjs              # dist/ にサイトを生成
node scripts/serve.mjs      # http://localhost:4323/brog-app/ で確認（変更を監視して自動で再ビルド）
node scripts/check-code.mjs # 記事中の Python コードの構文を確認
node scripts/make-icons.mjs # アプリアイコンを作り直す（ローカルの Chrome / Edge を使う）
```

`dist/index.html` をダブルクリックで開いても動く（この場合 PWA の機能は使えない）。

開発サーバーは公開先と同じ `/brog-app/` の下で配信する。404・オフラインページと Service Worker の動きを本番と揃えるため。

## 構成

```
content/articles/        記事の原稿（Markdown）
research/                記事ごとのリサーチメモ（出典付き）
docs/writing-guide.md    記事の書き方と記法
site.config.mjs          サイト名・公開 URL・カテゴリー
build.mjs                ビルドの入口
src/lib/                 Markdown 変換・ハイライト・フロー図・記事の読み込み
src/templates/           ページのテンプレート
src/assets/              CSS・JavaScript・Service Worker
public/icons/            アプリアイコン（scripts/make-icons.mjs で生成）
scripts/                 開発サーバー・コード確認
.claude/skills/write-article/   記事作成の手順（Claude Code が使う）
.github/workflows/pages.yml     GitHub Pages への自動デプロイ
```

## 機能

- 全文検索（タイトル・説明・タグ・本文）と、カテゴリー・難易度での絞り込み
- カテゴリー・タグ別の一覧
- 記事ページ: 追従する目次、読書進捗バー、難易度表示、関連記事
- コードのハイライト・ファイル名・行の強調・コピーボタン
- ` ```flow ` で書くフロー図（ビルド時に SVG へ変換）
- ライト / ダーク切り替え、スマホ対応、RSS
- PWA: ホーム画面やデスクトップにアプリとして追加できる。初回表示時に全記事を端末へ保存し、オフラインでも読める

### アイコン

ブログのフロー図をそのままモチーフにしている。上の箱がコード（`>_`）、下の箱が理解（整った行）、アンバーの矢印が「作って、分解して、理解する」のループ。
