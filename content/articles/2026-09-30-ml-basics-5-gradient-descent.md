機械学習の「学習」とは、予測の外れ具合（損失）が小さくなるようにパラメータ（重み）を少しずつ直していく作業だ。どちらに直せば損失が減るかを教えてくれるのが**勾配**（傾き）で、傾きの下る方向へ一歩ずつ進むのが**勾配降下法**（gradient descent）だ。霧の中で足元の傾きだけを頼りに山を下りる様子に似ている。

ニューラルネットの学習も、前回の勾配ブースティングも、この仕組みの上に乗っている。ライブラリを使えば 1 行で済むが、学習率を間違えたときに何が起きるかは、仕組みを知らないと判断できない。この記事では NumPy（Python の数値計算ライブラリ）だけで一から組み立てる。

> [!TIP] この記事で分かること
> - 勾配降下法の 1 回の更新式と、学習率が大きすぎる・小さすぎるときの振る舞い
> - 線形回帰を勾配降下法で学習させる方法（ライブラリなし）
> - フルバッチ・ミニバッチ・SGD の違いと、ミニバッチが標準になっている理由
> - Momentum・Adam・AdamW が解決した問題と、最近の Muon の位置づけ
> - 学習がうまくいかないときの確認の順番

連載「機械学習の基礎と使いどころ」の第 5 回。次回の深層学習は、今回の仕組みをそのまま使う。

| `#` | ここから行末までは説明（コメント）。動作には関係しない |
| `w -= lr * g` | `w = w - lr * g` の省略形。w を lr × g だけ減らす |

| `if ... elif ... :` | 条件で処理を分ける（elif は「そうでなくて、もし〜なら」） |

A([重みの初期値]) --> B[予測して損失を計算]

C --> D[重み -= 学習率 × 勾配]:::hl

## 1 回の更新は「傾きの逆向きに、学習率ぶん進む」

勾配降下法の更新式は 1 行だ。

> 新しい重み = 今の重み − 学習率 × 勾配

勾配は「重みを少し増やしたとき、損失がどれだけ増えるか」を表す。勾配が正なら重みを減らし、負なら増やせば損失は下がる。**学習率**（learning rate）は一歩の大きさで、人が決める設定値（ハイパーパラメータ）だ。

最も単純な例で試す。損失を f(w) = (w − 3)² とすると、最小になるのは w = 3 で、勾配は 2(w − 3) だ。w = 0 から始め、学習率を 3 通りに変える。

```python title="learning_rate.py" caption="同じ坂を、3 つの学習率で下る" {10}
import numpy as np  # 数値計算のライブラリ

def grad(w):  # 損失 (w − 3)² の勾配（傾き）
    return 2 * (w - 3)  # w が 3 より大きければ正、小さければ負になる

for lr in [0.1, 0.9, 1.1]:  # 学習率を 3 通り試す
    w = 0.0  # 出発点
    history = []  # 各回の w を記録するリスト
    for step in range(20):  # 20 回更新する
        w = w - lr * grad(w)  # ★ 傾きの逆向きに、学習率ぶん進む
        history.append(w)  # 記録する
    print(f"学習率 {lr:<4} 1〜4 回目 {np.round(history[:4], 2)}  20 回目 {history[19]:.2f}")
```

```text
学習率 0.1  1〜4 回目 [0.6  1.08 1.46 1.77]  20 回目 2.97
学習率 0.9  1〜4 回目 [5.4  1.08 4.54 1.77]  20 回目 2.97
学習率 1.1  1〜4 回目 [ 6.6  -1.32  8.18 -3.22]  20 回目 -112.01
```

3 つの振る舞いがはっきり分かれる。

| 学習率 | 振る舞い | 起きていること |
|---|---|---|
| 0.1 | 3 に向かって素直に近づく | 一歩が小さく、谷を越えない。小さすぎると時間がかかる |
| 0.9 | 3 の左右を行ったり来たりしながら近づく | 一歩が大きく、毎回谷を飛び越えるが、振れ幅は縮んでいく |
| 1.1 | 左右に振れながら遠ざかる（発散） | 飛び越えた先のほうが高くなり、振れ幅が毎回広がる |

実際の学習で損失のグラフが**上がり続ける、または NaN（計算不能）になる**ときは、まず学習率が大きすぎることを疑う。逆に、損失がいつまでもゆっくりとしか下がらないなら、学習率が小さすぎる可能性がある。

## 線形回帰を勾配降下法で学習させる

次は、データから直線 y = w·x + b を学習させる。損失は平均二乗誤差（予測と正解の差の二乗の平均）とし、w と b それぞれの勾配を計算して同時に更新する。

正解は y = 2x + 1 に雑音を足したもので、学習後に w ≈ 2、b ≈ 1 になれば成功だ。

```python title="linear_gd.py" caption="直線 y = w·x + b を勾配降下法で学習させる" {3,11,12}
rng = np.random.default_rng(0)  # 乱数の発生器
x = rng.uniform(0, 10, 200)  # 入力: 0〜10 の値を 200 個
y = 2 * x + 1 + rng.normal(0, 1, 200)  # ★ 正解は y = 2x + 1 に雑音を足したもの

w, b, lr = 0.0, 0.0, 0.01  # 傾き w と切片 b を 0 から始める。学習率は 0.01
for epoch in range(2001):  # データ全体を 2001 回なめる（1 回を 1 エポックと呼ぶ）
    err = (w * x + b) - y  # 予測 − 正解（200 個の誤差）
    loss = np.mean(err ** 2)  # 平均二乗誤差（損失）
    if epoch in (0, 10, 100, 500, 2000):  # 途中経過をいくつか表示する
        print(f"{epoch:>4} 回目  w={w:.3f}  b={b:.3f}  損失={loss:.3f}")
    grad_w = 2 * np.mean(err * x)  # ★ 損失を w で微分したもの（w の勾配）
    grad_b = 2 * np.mean(err)      # ★ 損失を b で微分したもの（b の勾配）
    w -= lr * grad_w  # w を更新する
    b -= lr * grad_b  # b を更新する

print(np.polyfit(x, y, 1))  # 比較: 数式で一発で解いた答え [傾き, 切片]
```

```text
   0 回目  w=0.000  b=0.000  損失=173.418
  10 回目  w=2.077  b=0.330  損失=1.164
 100 回目  w=2.042  b=0.576  損失=1.095
 500 回目  w=1.985  b=0.974  損失=1.043
2000 回目  w=1.975  b=1.047  損失=1.042
[1.97469853 1.04711649]
```

最初の 10 回で損失は 173 から 1.2 まで一気に下がる。そのあとは w と b の微調整が続き、2000 回目には数式で直接解いた答え（w = 1.975、b = 1.047）と一致した。

w は 10 回目でほぼ正しい値になるのに、b が 1 に近づくまでは数百回かかっている。x の範囲が 0〜10 と大きいため、w の勾配は b の勾配より大きくなりやすい。学習率は両方に共通なので、w に合わせて小さく取ると b の動きが遅くなる。この「方向によって傾きの急さが違う」問題が、後の節の Adam につながる。

> [!NOTE] 線形回帰なら数式で解ける。なぜ勾配降下法を使うのか
> 線形回帰には一発で解ける公式があるが、データが数千万件あると計算が重く、ニューラルネットのように公式が存在しないモデルもある。勾配降下法は「勾配が計算できれば何にでも使える」汎用性が強みだ。ニューラルネットでは、勾配を自動で計算する**誤差逆伝播法**を組み合わせる（第 6 回）。

## 全部見るか、少しずつ見るか：バッチサイズ

先ほどは、1 回の更新ごとに**全データ**で勾配を計算した（フルバッチ）。データが 100 万件あると、1 歩進むたびに 100 万件を計算することになり遅い。そこで、**一部のデータだけで勾配を見積もって**更新する方法が使われる。

| 方式 | 1 回の更新に使うデータ | 長所 | 短所 |
|---|---|---|---|
| フルバッチ | 全件 | 勾配が正確で、損失が滑らかに下がる | 1 歩が重い。メモリに載らないことも |
| SGD（確率的勾配降下法） | 1 件 | 1 歩が軽い。更新回数を稼げる | 勾配が雑音だらけで、ふらつく |
| ミニバッチ | 数十〜数百件（32、64、256 など） | 両者の中間。GPU で並列計算しやすい | バッチサイズという設定が 1 つ増える |

同じ 1,000 件のデータで、データ全体を 20 周（20 エポック）したときの結果を比べる。

```python title="batch_size.py" caption="バッチサイズを変えて、同じ 20 エポックだけ学習する（linear_gd.py の続き）" {9,12}
x = rng.uniform(0, 10, 1000)  # データを 1,000 件に増やす
y = 2 * x + 1 + rng.normal(0, 1, 1000)

def train(batch, epochs=20, lr=0.01):  # batch 件ずつ使って学習する関数
    r = np.random.default_rng(0)  # 並べ替え用の乱数
    w = b = 0.0  # 0 から始める
    updates = 0  # 更新した回数
    for _ in range(epochs):  # データ全体を epochs 周する
        idx = r.permutation(len(x))  # ★ 毎周、データの順番をシャッフルする
        for start in range(0, len(x), batch):  # batch 件ずつ区切って取り出す
            i = idx[start:start + batch]  # 今回使うデータの番号
            err = w * x[i] + b - y[i]  # ★ その一部のデータだけで誤差を計算する
            w -= lr * 2 * np.mean(err * x[i])  # 一部のデータから見積もった勾配で更新
            b -= lr * 2 * np.mean(err)
            updates += 1
    return np.mean((w * x + b - y) ** 2), updates  # 全データでの最終損失と更新回数

for name, bs in [("フルバッチ", 1000), ("ミニバッチ 32", 32), ("SGD (1 件)", 1)]:
    loss, n = train(bs)
    print(f"{name:<12} 更新回数 {n:>6}  最終損失 {loss:.3f}")
```

```text
フルバッチ        更新回数     20  最終損失 1.128
ミニバッチ 32     更新回数    640  最終損失 1.077
SGD (1 件)    更新回数  20000  最終損失 1.186
```

同じ計算量（20 エポック）でも、結果は違う。フルバッチは勾配こそ正確だが、20 回しか更新できず下りきれていない。SGD は 2 万回更新したが、1 件ごとの勾配が雑音だらけで、最後まで谷底の周りをふらついている。ミニバッチは十分な回数を、ほどよく正確な勾配で更新でき、最も低い損失になった。

深層学習では、ミニバッチ SGD が事実上の標準だ。単に「SGD」と書かれていても、実際にはミニバッチを指していることが多い。

> [!TIP] バッチサイズを変えたら学習率も見直す
> バッチサイズを大きくすると勾配の雑音が減るので、学習率を大きくできることが多い。逆に、バッチサイズだけを変えて学習率をそのままにすると、学習が遅くなったり不安定になったりする。2 つは組で調整する。

## Momentum と Adam：細長い谷を速く下る

実際の損失の地形は、きれいなお椀ではない。ある方向には急で、別の方向には緩い**細長い谷**になっていることが多い。特徴量の単位がばらばら（年齢は 0〜100、年収は 0〜数千万）なときに典型的に起きる。

細長い谷では、学習率を急な方向に合わせて小さくしないと発散する。すると緩い方向の歩みが遅くなる。これを改良したのが次の手法だ。

| 手法 | 考え方 | たとえ |
|---|---|---|
| SGD | 今の勾配だけで進む | 足元の傾きだけを見て一歩ずつ |
| Momentum | 過去の勾配を溜めて「勢い」として使う | 転がるボール。振動は打ち消し合い、一貫した方向には加速する |
| Adam | 勢いに加え、方向ごとに一歩の大きさを自動で調整する | 急な方向は小股、緩い方向は大股で歩く |
| AdamW | Adam の「重み減衰（L2 正則化）」のかけ方を直したもの | Adam と同じ。正則化が正しく効く |

一方向の傾きがもう一方の 50 倍急な谷で、到達までの回数を比べる。

```python title="optimizers.py" caption="細長い谷で SGD・Momentum・Adam を比べる" {1,19,26}
scale = np.array([1.0, 50.0])  # ★ 2 つ目の方向は 50 倍急な谷

def loss(p):  # 損失: 0.5 × (a² + 50 b²)。最小は (0, 0)
    return 0.5 * np.sum(scale * p ** 2)

def grad(p):  # 勾配
    return scale * p

def run(method, lr, max_steps=5000):  # 指定の手法で損失 0.001 未満まで下る
    p = np.array([10.0, 1.0])  # 出発点
    v = np.zeros(2)  # Momentum の「勢い」
    m = np.zeros(2)  # Adam: 勾配の平均（勢い）
    s = np.zeros(2)  # Adam: 勾配の 2 乗の平均（方向ごとの急さ）
    for t in range(1, max_steps + 1):
        g = grad(p)  # 今いる場所の勾配
        if method == "SGD":
            p = p - lr * g  # 勾配だけで進む
        elif method == "Momentum":
            v = 0.9 * v + g  # ★ 過去の勾配を 9 割残して足し込む
            p = p - lr * v
        elif method == "Adam":
            m = 0.9 * m + 0.1 * g       # 勾配の移動平均
            s = 0.999 * s + 0.001 * g ** 2  # 勾配の 2 乗の移動平均
            m_hat = m / (1 - 0.9 ** t)    # 最初の数回の偏りを補正する
            s_hat = s / (1 - 0.999 ** t)
            p = p - lr * m_hat / (np.sqrt(s_hat) + 1e-8)  # ★ 急な方向ほど一歩を小さく
        if loss(p) < 1e-3:
            return f"{t:>4} 回で到達"
        if loss(p) > 1e6:
            return f"{t:>4} 回目で発散"
    return "未到達"

for method, lr in [("SGD", 0.035), ("SGD", 0.045), ("Momentum", 0.035), ("Adam", 0.3)]:
    print(f"{method:<9} 学習率 {lr:<6} {run(method, lr)}")
```

```text
SGD       学習率 0.035   152 回で到達
SGD       学習率 0.045    24 回目で発散
Momentum  学習率 0.035    93 回で到達
Adam      学習率 0.3      86 回で到達
```

SGD は、学習率を 0.035 から 0.045 に少し上げただけで発散する。急な方向（傾き 50 倍）の限界に合わせるしかなく、緩い方向の歩みが遅いまま 152 回かかった。Momentum は同じ学習率でも、一貫した方向に勢いがつき 93 回で着く。Adam は方向ごとに一歩の大きさを割り算で揃えるので、**10 倍近い学習率**でも発散せず 86 回で着いた。

Adam が既定の選択肢として広く使われているのは、この「学習率を多少雑に決めても動く」頑健さのためだ。

> [!IMPORTANT] Adam で正則化するなら AdamW を使う
> Adam に L2 正則化を損失として足すと、方向ごとの割り算が正則化にもかかり、本来の効果が弱まる。Loshchilov と Hutter は、重みを直接少しずつ縮める**重み減衰**を勾配の更新と切り離した AdamW を提案した。深層学習のライブラリでは、Adam と AdamW が別のものとして用意されている。正則化をかけるなら AdamW を選ぶ。

## 学習率は固定しない：ウォームアップと減衰

実務では、学習率を学習の途中で変える**スケジュール**を組み合わせる。

| スケジュール | 動き | 目的 |
|---|---|---|
| ウォームアップ | 最初の数百〜数千回、学習率を 0 から徐々に上げる | 学習の初期、重みが乱雑な段階で大きく飛ばされるのを防ぐ |
| ステップ減衰 | 一定エポックごとに学習率を 1/10 にする | 谷の近くでは一歩を小さくして、底に落ち着かせる |
| コサイン減衰 | 学習率をコサインの形でなめらかに 0 付近まで下げる | ステップ減衰を滑らかにしたもの。大規模モデルの学習で広く使われる |
| 検証の損失で下げる | 検証の損失が改善しなくなったら下げる | エポック数を事前に決めにくいときに |

## 活用事例と最近の動向

勾配降下法は、それ単体でアプリケーションになるものではなく、多くの手法の**学習エンジン**として働いている。

| 使われる場所 | 何を勾配降下法で決めているか |
|---|---|
| ニューラルネット全般（画像・音声・言語） | 数百万〜数千億個の重み。ミニバッチ + Adam/AdamW が標準 |
| 推薦システムの行列分解 | 利用者と商品それぞれを表すベクトル。Netflix Prize の上位手法の中心は、SGD で学習する行列分解だった |
| 広告のクリック率予測 | 毎日届く大量のログで、ロジスティック回帰をオンライン（逐次）に学習する |
| 勾配ブースティング | 重みではなく「次に足す木」を、損失の勾配を目標にして決める（第 4 回） |

最適化手法の研究は今も続いている。2025 年には、重み行列の更新方向を直交化する **Muon** を大規模言語モデルの学習に使い、計算量あたりの学習効率が AdamW の約 2 倍になったという報告が出た。ただし報告の中心は大規模モデルの事前学習で、小〜中規模のモデルや表形式データでの優位はまだ確かめられていない。実務の既定は、当面 Adam/AdamW でよい。

## 最適化手法と学習率の選び方

```flow caption="学習がうまくいかないときの確認の順番"
A([損失が下がらない]) --> B{損失が増える\nまたは NaN?}
B -- はい --> C[学習率を 1/10 に]:::hl
B -- いいえ --> D{特徴量の尺度は\n揃っている?}
D -- いいえ --> E[標準化する]
D -- はい --> F{ゆっくりしか\n下がらない?}
F -- はい --> G[学習率を 3〜10 倍に\nまたは Adam に]
F -- いいえ --> H([モデルやデータを見直す])
```

| 状況 | 選ぶもの |
|---|---|
| 深層学習で、まず動かしたい | AdamW。学習率 1e-3 前後から始め、ウォームアップとコサイン減衰を付ける |
| 画像分類などで、最後の汎化性能を詰めたい | Momentum 付き SGD も試す（丁寧に調整すると Adam より汎化が良い例が報告されている） |
| 線形モデル・ロジスティック回帰 | ライブラリの既定のソルバー（勾配降下法以外の高速な解法）で十分 |
| データが大きすぎてメモリに載らない、毎日データが届く | ミニバッチ SGD でオンライン学習 |

## 勾配降下法のチェックリスト

| 確かめること | 対応する節 |
|---|---|
| 損失の推移をグラフにして、上がっていないか見た | 学習率 |
| 損失が増える・NaN になるなら、まず学習率を下げた | 学習率 |
| 特徴量の尺度を揃えた（細長い谷を作らない） | Momentum と Adam |
| バッチサイズを変えたら学習率も見直した | バッチサイズ |
| Adam で正則化するなら AdamW を使った | Momentum と Adam |
| ウォームアップと減衰のスケジュールを組んだ | スケジュール |

勾配降下法は「傾きを見て一歩進む」だけの素朴な仕組みだ。それでも、学習率・バッチサイズ・最適化手法の 3 つを押さえておけば、学習がうまくいかないときの原因の多くに当たりを付けられる。

次回「[深層学習はいつ使うべきか](2026-09-30-ml-basics-6-deep-learning.html)」では、今回の勾配降下法に誤差逆伝播法を組み合わせ、PyTorch でニューラルネットを学習させる。
