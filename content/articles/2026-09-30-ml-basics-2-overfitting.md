学習に使ったデータでは誤差ほぼゼロなのに、新しいデータに当てると大きく外れる。機械学習でいちばんよく起きる失敗が、この**過学習**（overfitting）だ。モデルがデータの本質的な傾向だけでなく、そのデータにたまたま含まれていた雑音まで覚えてしまうことで起きる。

過学習は目で見ても分からない。だから**数字で見える化する仕組み**を先に作り、そのうえで抑える手段を選ぶ。この記事ではその順番で進める。

> [!TIP] この記事で分かること
> - 過学習と学習不足を、訓練誤差とテスト誤差の差で見分ける方法
> - 検証曲線・学習曲線で「モデルを単純にすべきか、データを増やすべきか」を判断する方法
> - L1（Lasso）と L2（Ridge）の正則化が、それぞれ何を罰しているか
> - 交差検証の正しい使い方と、点数を水増しする「データ漏れ」の防ぎ方
> - 深層学習で見られる「二重降下」と、従来の常識との関係

## 覚えすぎと学ばなすぎ：誤差の差で見分ける

過学習の反対は**学習不足**（underfitting）で、モデルが単純すぎて傾向すら捉えられていない状態だ。2 つは、訓練誤差とテスト誤差の組み合わせで見分けられる。

| 状態 | 訓練誤差 | テスト誤差 | 例え | 主な対策 |
|---|---|---|---|---|
| 学習不足 | 大きい | 大きい | 教科書を読んでいない | モデルを複雑にする、特徴量を増やす |
| ちょうどよい | 小さい | 小さい（訓練と近い） | 考え方を理解している | — |
| 過学習 | とても小さい | 大きい | 過去問の答えを丸暗記した | 正則化、単純なモデル、データを増やす |

これは**バイアスとバリアンスのトレードオフ**とも呼ばれる。バイアスは「考え方そのものの偏り」（単純すぎて外れる）、バリアンスは「学習データが変わると結果が大きく揺れる度合い」（複雑すぎて雑音に合わせる）だ。モデルを複雑にするとバイアスは減り、バリアンスは増える。

サイン波に雑音を足した 20 点のデータに、次数（曲線の曲がりやすさ）の違う多項式を当てはめて確かめる。

```python title="polynomial.py" caption="次数を変えて訓練誤差とテスト誤差を比べる" {11,14,21}
import numpy as np  # 数値計算のライブラリ
from sklearn.pipeline import make_pipeline  # 前処理とモデルをつなぐ
from sklearn.preprocessing import PolynomialFeatures, StandardScaler  # x を x, x², x³… に広げる / 尺度を揃える
from sklearn.linear_model import LinearRegression  # 直線（重み付きの足し算）で当てはめるモデル
from sklearn.metrics import root_mean_squared_error  # 誤差の大きさ（RMSE）

rng = np.random.default_rng(0)  # 乱数の発生器。0 を指定して毎回同じ結果にする

def make_data(n):  # n 件のデータを作る関数
    x = rng.uniform(0, 1, n)  # 0〜1 の間の x をランダムに n 個
    y = np.sin(2 * np.pi * x) + rng.normal(0, 0.3, n)  # ★ 本当の関係（サイン波）＋雑音
    return x.reshape(-1, 1), y  # x を「n 行 1 列の表」の形にして返す

X_tr, y_tr = make_data(20)   # ★ 学習用はたった 20 件
X_te, y_te = make_data(200)  # テスト用は 200 件（未知のデータの代わり）

for d in [1, 4, 15]:  # 次数 1（直線）・4・15 を試す
    m = make_pipeline(PolynomialFeatures(d, include_bias=False),  # x を d 次まで広げる
                      StandardScaler(), LinearRegression()).fit(X_tr, y_tr)  # 学習する
    tr = root_mean_squared_error(y_tr, m.predict(X_tr))  # 訓練データでの誤差
    te = root_mean_squared_error(y_te, m.predict(X_te))  # ★ テストデータでの誤差
    print(f"次数 {d:>2}  訓練 {tr:.3f}  テスト {te:.3f}")
```

```text
次数  1  訓練 0.576  テスト 0.564
次数  4  訓練 0.188  テスト 0.374
次数 15  訓練 0.110  テスト 24.125
```

次数 1 は訓練もテストも悪い（学習不足）。次数 15 は訓練誤差が最も小さいのに、テスト誤差は 24 と桁違いに悪い（過学習）。20 点すべてを通ろうとして、点と点の間で曲線が大きく暴れたためだ。雑音の大きさ（0.3）に近い誤差で両方を抑えている次数 4 が、この中ではちょうどよい。

> [!WARNING] 訓練データの点数だけで喜ばない
> 訓練データの点数は、モデルを複雑にすればいくらでも上がる。報告する点数は、学習に使っていないデータで測ったものだけにする。

## 検証曲線と学習曲線で「次の一手」を決める

過学習していると分かったら、次に決めるべきは「モデルを単純にするか、データを増やすか」だ。これを判断する 2 つのグラフがある。

| グラフ | 横軸 | 分かること |
|---|---|---|
| 検証曲線（validation curve） | モデルの複雑さ（木の深さ、正則化の強さなど） | どの複雑さで検証の点数が最も良いか |
| 学習曲線（learning curve） | 学習データの件数 | データを増やせば改善しそうか |

乳がん診断データ（569 件、30 項目）で、決定木（次回扱う、質問を重ねて分類するモデル）の深さを変えた検証曲線を取る。

```python title="validation_curve.py" caption="木の深さを変えて、訓練と検証の点数の差を見る" {8,13}
from sklearn.datasets import load_breast_cancer  # 乳がん診断の練習用データ
from sklearn.model_selection import validation_curve  # 検証曲線を計算する関数
from sklearn.tree import DecisionTreeClassifier  # 決定木（質問を重ねて分類するモデル）

X, y = load_breast_cancer(return_X_y=True)  # 入力 X と正解 y を読み込む
depths = [1, 2, 3, 5, 8, 12]  # 試す深さ（質問を重ねる回数の上限）

tr, va = validation_curve(  # ★ 深さごとに 5 分割の交差検証を行う
    DecisionTreeClassifier(random_state=0), X, y,
    param_name="max_depth", param_range=depths, cv=5)

for d, a, b in zip(depths, tr.mean(1), va.mean(1)):  # 深さごとに 5 回の平均を表示する
    print(f"深さ {d:>2}  訓練 {a:.3f}  検証 {b:.3f}  差 {a-b:.3f}")  # ★ 差が過学習の度合い
```

```text
深さ  1  訓練 0.924  検証 0.900  差 0.025
深さ  2  訓練 0.952  検証 0.928  差 0.024
深さ  3  訓練 0.974  検証 0.917  差 0.057
深さ  5  訓練 0.991  検証 0.916  差 0.076
深さ  8  訓練 1.000  検証 0.916  差 0.084
深さ 12  訓練 1.000  検証 0.917  差 0.083
```

深さを増やすと訓練の点数は 1.000（満点）まで上がるが、検証の点数は深さ 2 の 0.928 が最も高い。それより深くしても検証は上がらず、差だけが広がる。このデータでは「深さ 2〜3 で止める」のが答えになる。

次は学習曲線だ。手書き数字データ（1,797 件）で、深さを制限しない決定木に与えるデータ量を変える。

```python title="learning_curve.py" caption="データを増やすと、訓練と検証の差は縮むか" {6}
from sklearn.datasets import load_digits  # 手書き数字（8×8 画素）の練習用データ
from sklearn.model_selection import learning_curve  # 学習曲線を計算する関数

X, y = load_digits(return_X_y=True)  # 1,797 枚の画像と、その数字

sizes, tr, va = learning_curve(  # ★ 学習データを 10%・25%・50%・100% に変えて評価する
    DecisionTreeClassifier(random_state=0), X, y,
    train_sizes=[0.1, 0.25, 0.5, 1.0], cv=5, shuffle=True, random_state=0)

for n, a, b in zip(sizes, tr.mean(1), va.mean(1)):  # 件数ごとに結果を表示する
    print(f"学習件数 {n:>5}  訓練 {a:.3f}  検証 {b:.3f}  差 {a-b:.3f}")
```

```text
学習件数   143  訓練 1.000  検証 0.610  差 0.390
学習件数   359  訓練 1.000  検証 0.727  差 0.273
学習件数   718  訓練 1.000  検証 0.752  差 0.248
学習件数  1437  訓練 1.000  検証 0.786  差 0.214
```

訓練の点数は常に満点で、深さ無制限の木は何件でも丸暗記できることが分かる。一方、検証の点数はデータを増やすたびに上がり、差は 0.39 から 0.21 まで縮んだ。**曲線がまだ上り続けているなら、データを増やすことが効く**。逆に、検証の点数が横ばいになっていたら、データを集めるよりモデルや特徴量を見直す方が効く。

## 正則化は「複雑さ」に罰金を課す

データを増やせないとき、過学習を抑える代表的な手段が**正則化**（regularization）だ。モデルが誤差を小さくしようとするとき、同時に「複雑さ」にも罰金を課し、両方の合計を小さくさせる。

線形モデル（重み付きの足し算で予測するモデル）では、複雑さを**重み（係数）の大きさ**で測る。先ほどの次数 15 のモデルが暴れたのは、係数が極端に大きくなったからだ。

| 種類 | 罰金の計算 | 効き方 | 向く場面 |
|---|---|---|---|
| L2（Ridge） | 係数の二乗の合計 | すべての係数を少しずつ 0 に近づける | 特徴量がどれも少しずつ効いている |
| L1（Lasso） | 係数の絶対値の合計 | 不要な係数をちょうど 0 にする（特徴選択になる） | 効く特徴量は一部だけ、と考えられる |
| Elastic Net | L1 と L2 の混合 | 両方の中間。相関の強い特徴量の組を一緒に残す | 特徴量どうしの相関が強い |

罰金の強さは `alpha` で決める。大きいほど単純なモデルになる。次数 15 のモデルに正則化をかけて比べる。

```python title="regularization.py" caption="次数 15 のモデルに L1・L2 正則化をかける（polynomial.py の続き）" {4,5}
from sklearn.linear_model import Ridge, Lasso  # L2 正則化と L1 正則化の線形モデル

models = [("なし", LinearRegression()),  # 正則化なし
          ("L2 Ridge", Ridge(alpha=0.1)),  # ★ 係数の二乗に罰金
          ("L1 Lasso", Lasso(alpha=0.01, max_iter=100000))]  # ★ 係数の絶対値に罰金

for name, reg in models:  # 3 種類を順に試す
    m = make_pipeline(PolynomialFeatures(15, include_bias=False),  # 同じ次数 15
                      StandardScaler(), reg).fit(X_tr, y_tr)  # 尺度を揃えてから学習する
    coef = m[-1].coef_  # 最後の部品（モデル）の係数 15 個
    te = root_mean_squared_error(y_te, m.predict(X_te))  # テストでの誤差
    zeros = np.sum(np.abs(coef) < 1e-8)  # ちょうど 0 になった係数の数
    print(f"{name:<9} テスト {te:.3f}  係数の最大 {np.abs(coef).max():8.1e}  ゼロ {zeros}/15")
```

```text
なし        テスト 24.125  係数の最大  2.1e+09  ゼロ 0/15
L2 Ridge  テスト 0.342  係数の最大  1.7e+00  ゼロ 0/15
L1 Lasso  テスト 0.417  係数の最大  2.5e+00  ゼロ 12/15
```

正則化なしでは係数が 21 億（2.1e+09）まで膨らんでいた。L2 をかけると最大 1.7 に抑えられ、テスト誤差は 24 から 0.34 に下がる。次数 4 のモデルより良い結果だ。

L1 では 15 個中 12 個の係数がちょうど 0 になり、**残った 3 つの項だけで予測するモデル**になった。どの特徴量が効いているかを知りたいときは、L1 が役に立つ。

> [!IMPORTANT] 正則化の前に尺度を揃える
> 正則化は係数の大きさを罰するので、特徴量の単位（円と万円など）がばらばらだと、単位の小さい特徴量ほど不当に罰される。`StandardScaler` で平均 0・ばらつき 1 に揃えてから正則化する。

### モデルの種類ごとの「正則化」

正則化の考え方は線形モデル以外にもある。名前は違っても「複雑になりすぎないよう制限をかける」点は同じだ。

| モデル | 正則化にあたるもの | 扱う回 |
|---|---|---|
| 線形モデル | L1・L2（`alpha`、`C`）。`C` は `alpha` の逆数で、小さいほど強い | この回 |
| 決定木 | 深さの上限、葉の最小件数、剪定（`ccp_alpha`） | 第 3 回 |
| 勾配ブースティング | 学習率、木の数の早期終了、葉の数、サンプリング | 第 4 回 |
| ニューラルネット | 重み減衰（L2）、Dropout、早期終了、データ拡張 | 第 6 回 |

## 交差検証の点数を水増しする「データ漏れ」

ここまで、学習に使っていないデータで測ることを繰り返してきた。データを 1 回だけ分けると、分け方の運で点数がぶれる。そこで、データを k 個に分け、1 つを検証用、残りを学習用にして k 回繰り返し、平均を取る。これが**交差検証**（cross-validation）だ。

交差検証で最も多い失敗は、**検証用データの情報が学習側に漏れる**ことだ。これを**データ漏れ**（leakage）と呼ぶ。典型的なのは、特徴量の選択や尺度の調整を、交差検証の前にデータ全体で行ってしまうケースだ。

次のコードで、中身がまったくの乱数（正解を予測できる情報が一切ない）データを使って確かめる。本来なら正解率は 0.5（当てずっぽう）になるはずだ。

```python title="leakage.py" caption="乱数のデータでも、特徴選択の順番を間違えると 85% 当たって見える" {7,11,15}
import numpy as np  # 数値計算のライブラリ
from sklearn.feature_selection import SelectKBest, f_classif  # 正解と関係の強い特徴量を選ぶ
from sklearn.linear_model import LogisticRegression  # 単純な分類モデル
from sklearn.model_selection import cross_val_score  # 交差検証で点数を出す関数

rng = np.random.default_rng(0)  # 乱数の発生器
X = rng.normal(size=(100, 5000))  # ★ 100 件 × 5,000 列の完全な乱数
y = rng.integers(0, 2, 100)       # 正解も 0/1 の乱数。予測できる情報は一切ない

# 誤り: 全データを見て「正解と関係ありそうな 20 列」を選んでから交差検証する
X_sel = SelectKBest(f_classif, k=20).fit_transform(X, y)  # ★ 検証用データの正解も見て選んでいる
print(f"漏れあり {cross_val_score(LogisticRegression(), X_sel, y, cv=5).mean():.2f}")

# 正しい: 特徴選択もパイプラインに入れ、学習用データの中だけで行う
pipe = make_pipeline(SelectKBest(f_classif, k=20), LogisticRegression())  # ★ 選択とモデルを一体に
print(f"漏れなし {cross_val_score(pipe, X, y, cv=5).mean():.2f}")
```

```text
漏れあり 0.85
漏れなし 0.48
```

5,000 列もあれば、偶然だけで正解とよく一致する列が必ず見つかる。全データで選ぶと、その偶然を検証用データについても使ってしまうため、乱数なのに 85% 当たって見える。パイプラインに入れれば、選択は毎回学習用データの中だけで行われ、正しく 0.5 前後になる。

| データ漏れの型 | 例 | 防ぎ方 |
|---|---|---|
| 前処理の漏れ | 全データで平均・ばらつきを計算してから分割する | 前処理を `Pipeline` に入れる |
| 時間の漏れ | 未来のデータで学習し、過去を予測している | `TimeSeriesSplit` で、常に過去から未来を予測する |
| 集団の漏れ | 同じ患者・同じ顧客のデータが学習と検証の両方にある | `GroupKFold` で、同じ人を同じ側にまとめる |
| 答えの漏れ | 「解約日」のように、結果が出た後にしか分からない項目が特徴量にある | 予測する時点で本当に手に入る項目だけを使う |

> [!WARNING] 検証の点数を見ながら何百回も調整しない
> 交差検証の点数を見て設定を何百通りも試すと、検証用データにも過学習する。最終的な性能は、調整に一度も使っていないテスト用データで**一度だけ**測る。Kaggle でも、公開順位表（public leaderboard）の点数に合わせすぎたチームが、最終順位で大きく順位を落とす現象が「shake-up」として知られている。

## 活用事例：過学習が起きやすい現場

過学習は、**データの件数に対して特徴量や自由度が多い**ときに起きやすい。次の表は、実務でよく出会う場面と、効きやすい対策をまとめたものだ。

| 分野 | 起きやすい理由 | 効きやすい対策 |
|---|---|---|
| 医療・創薬 | 患者数が数百件なのに、検査項目や遺伝子の数が数千〜数万 | L1 正則化で項目を絞る。`GroupKFold` で同じ患者を分ける |
| 与信・審査 | 項目は多いが、貸し倒れの件数は少ない | 正則化付きロジスティック回帰や浅い木。時間で分けた検証 |
| 需要予測 | 過去のキャンペーンなど一度きりの出来事を覚えてしまう | `TimeSeriesSplit`。特徴量を予測時点で手に入るものに限る |
| 画像分類（少量データ） | 数百枚の画像に対し、パラメータが数百万 | データ拡張（回転・反転）、学習済みモデルの流用、Dropout |
| 広告・推薦 | ID のような種類の多い項目を丸暗記する | 出現回数の少ない値をまとめる、L2、埋め込みの次元を小さく |

## 発展：大きなモデルほど過学習しない？ 二重降下

ここまでの説明は「モデルを複雑にしすぎると過学習する」という古典的な考え方に沿っている。ところが深層学習では、それだけでは説明できない現象が報告されている。

OpenAI の Nakkiran らは 2019 年、CNN・ResNet・Transformer で、モデルを大きくしていくとテスト誤差が「下がる → 上がる → **再び下がる**」という**二重降下**（double descent）を示した。誤差が最も悪くなるのは、モデルが訓練データをちょうど丸暗記できる大きさのあたりで、それを超えてさらに大きくすると再び良くなる。同じ現象は学習の回数（エポック数）に対しても起き、ラベルの誤りが多いデータで目立つ。

```flow caption="二重降下。古典的な U 字の先に、2 回目の下り坂がある"
direction LR
A([小さいモデル]) --> B[誤差が下がる]
B --> C[丸暗記できる境目で\n誤差が最悪]:::hl
C --> D[さらに大きくすると\n再び下がる]
D --> E([大きいモデル])
```

これは「正則化は要らない」という意味ではない。実務での受け取り方は次の 3 点だ。

- 表形式データの小〜中規模のモデル（この連載の大半）では、古典的な U 字の考え方と正則化がそのまま効く
- 深層学習で「少し大きくしたら悪化した」とき、さらに大きくすると改善する可能性がある
- どちらの場合も、判断の根拠は検証用データの点数だ。理論ではなく曲線を見て決める

## 過学習対策のチェックリスト

| 確かめること | 対応する節 |
|---|---|
| 訓練とテストの両方の点数を並べて報告している | 誤差の差で見分ける |
| 検証曲線で複雑さを、学習曲線でデータ量の効果を確かめた | 検証曲線と学習曲線 |
| 線形モデルでは尺度を揃えてから L1/L2 をかけた | 正則化 |
| 前処理・特徴選択をパイプラインに入れ、交差検証の中で行っている | データ漏れ |
| 時系列・同一人物のデータを、分け方で漏らしていない | データ漏れの型 |
| テスト用データは最後に一度だけ使った | データ漏れ |

過学習は「モデルの性能が悪い」のではなく、「測り方が甘いせいで悪さに気づけない」問題でもある。見える化の仕組みがあれば、打つ手は自然と決まる。

次回「[決定木は「質問の順番」を学ぶ](2026-09-30-ml-basics-3-decision-tree.html)」では、今回の検証曲線にも登場した決定木を分解する。深さを制限しない木がなぜ満点を取れてしまうのかも、仕組みから説明する。
