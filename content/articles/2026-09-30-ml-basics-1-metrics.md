機械学習のモデルを作ると、最初に「正解率 98%」のような数字が出てくる。高く見えるが、この数字だけでは使えるモデルかどうかは分からない。不正な取引が 2% しかないデータなら、**すべてを「正常」と答えるだけで正解率は 98% になる**からだ。

評価指標は、モデルを作り終えてから選ぶものではない。「どんな間違いが、どれだけ高くつくか」を先に決め、それを測れる指標を選ぶ。この連載は評価指標から始める。次回以降で扱う手法の良し悪しは、すべてここで選んだ物差しで測ることになる。

> [!TIP] この記事で分かること
> - 正解率が当てにならない場面と、その見抜き方
> - 混同行列から適合率・再現率・F1 を読む方法
> - ROC-AUC と PR-AUC の違いと、「不均衡データなら PR-AUC」という通説の限界
> - 誤りのコストから閾値を決める方法（`TunedThresholdClassifierCV`）
> - 回帰の指標 MAE・RMSE・MAPE が、同じ予測に違う順位を付ける理由

連載「機械学習の基礎と使いどころ」は全 8 回で、評価指標 → 過学習と正則化 → 決定木 → アンサンブル → 勾配降下法 → 深層学習 → クラスタリング → 次元削減の順に進む。コードは scikit-learn（Python の機械学習ライブラリ）で書き、ネットにつながなくても動くデータだけを使う。

| 記号 | 意味 |
|---|---|
| `#` | ここから行末までは説明（コメント）。動作には関係しない |
| `import` / `from ... import` | ライブラリ（他の人が作った部品集）を読み込む |
| `def 名前():` | 関数（ひとまとまりの処理）を作る |
| `[ ]` | リスト。順番のある入れ物 |
| `X` / `y` | 慣習で、`X` は入力（特徴量の表）、`y` は正解ラベル |
| `f"...{値}"` | 文字列の中に値を埋め込む書き方 |

```flow caption="評価指標を選ぶ流れ。指標はモデルより先に決める"
A([課題]) --> B{予測するのは?}
B -- カテゴリー --> C[混同行列を作る]
B -- 数値 --> D[MAE / RMSE / MAPE]
C --> E{高くつく誤りは?}:::hl
E -- 見逃し --> F[再現率を重視]
E -- 誤検知 --> G[適合率を重視]
F --> H([コストで閾値を決める])
G --> H
```

## 正解率 98% でも何も見つけない：不均衡データの落とし穴

正解率（accuracy）は「全件のうち当たった割合」だ。分かりやすいが、クラスの数が偏っている**不均衡データ**では役に立たない。不正検知、故障予測、病気のスクリーニングなど、実務で機械学習を使いたい場面の多くは、見つけたいもの（正例）が数 % 以下の不均衡データだ。

次のコードは、正例が 2.5% のデータを作り、「常に多い方のクラスを答える」だけのモデルを評価する。

```python title="accuracy_trap.py" caption="何も学ばないモデルでも正解率は 97.5% になる" {6,12}
from sklearn.datasets import make_classification  # 練習用のデータを作る関数
from sklearn.model_selection import train_test_split  # データを学習用とテスト用に分ける関数
from sklearn.dummy import DummyClassifier  # 何も学ばない「比較用の基準モデル」
from sklearn.metrics import accuracy_score, recall_score  # 正解率と再現率を計算する関数

# ★ 2 万件、正例（見つけたいもの）が約 2% の不均衡データを作る
X, y = make_classification(n_samples=20000, n_features=20, n_informative=5,
                           weights=[0.98], flip_y=0.01, class_sep=0.8, random_state=0)
# 7 割を学習用、3 割をテスト用に分ける。stratify=y で両方の正例の割合を揃える
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.3, stratify=y, random_state=0)

# ★ 常に「多い方のクラス（正常）」と答えるだけのモデル
dummy = DummyClassifier(strategy="most_frequent").fit(X_tr, y_tr)
pred = dummy.predict(X_te)  # テスト用データに対する予測（すべて 0）

print(f"正解率 {accuracy_score(y_te, pred):.3f}")  # 当たった割合
print(f"再現率 {recall_score(y_te, pred):.3f}")    # 正例のうち見つけられた割合
```

```text
正解率 0.975
再現率 0.000
```

正解率は 97.5% なのに、見つけたい正例は 1 件も見つけていない。このため、不均衡データでは**まず「何も学ばないモデル」の点数を測る**。これが比較の基準線（ベースライン）になり、本物のモデルがこれを超えて初めて学習に意味があったと言える。

> [!WARNING] 正解率だけを報告しない
> 「正解率 98%」と報告されたら、正例の割合を聞き返す。正例が 2% なら、その数字は何も学ばないモデルと同じだ。

## 混同行列で「どう間違えたか」を分解する

正解率が 1 つの数字にまとめてしまう情報を、4 つのマスに分けて見るのが**混同行列**（confusion matrix）だ。予測と正解の組み合わせは次の 4 通りしかない。

| | 予測: 陰性（正常） | 予測: 陽性（異常） |
|---|---|---|
| **正解: 陰性** | TN（正しく見逃した） | FP（誤検知。空振り） |
| **正解: 陽性** | FN（見逃し） | TP（正しく見つけた） |

ここから、目的に応じて 3 つの指標を作る。

| 指標 | 式 | 問い | 重視する場面 |
|---|---|---|---|
| 適合率（precision） | TP ÷ (TP + FP) | 「陽性」と言ったもののうち、本当に陽性だった割合は? | 誤検知が高くつく。スパム判定（大事なメールを消すと困る） |
| 再現率（recall） | TP ÷ (TP + FN) | 本当の陽性のうち、見つけられた割合は? | 見逃しが高くつく。がん検診、不正検知 |
| F1 | 適合率と再現率の調和平均 | 両方をバランスよく満たしているか? | どちらのコストも同程度で、1 つの数字で比べたい |

同じデータでロジスティック回帰（確率を出す単純な分類モデル）を学習させ、混同行列と各指標を見る。

```python title="confusion.py" caption="混同行列と適合率・再現率・F1（accuracy_trap.py の続き）" {8,10}
from sklearn.linear_model import LogisticRegression  # 確率を出す単純な分類モデル
from sklearn.metrics import (confusion_matrix, precision_score,  # 混同行列・適合率
                             recall_score, f1_score)  # 再現率・F1

model = LogisticRegression(max_iter=1000).fit(X_tr, y_tr)  # 学習用データで学習する
pred = model.predict(X_te)  # テスト用データを分類する（確率 0.5 以上なら陽性）

print(confusion_matrix(y_te, pred))  # ★ [[TN FP] [FN TP]] の順に並ぶ
print(f"適合率 {precision_score(y_te, pred):.3f}")  # 陽性と言ったうち当たった割合
print(f"再現率 {recall_score(y_te, pred):.3f}")     # ★ 本物の陽性を見つけた割合
print(f"F1     {f1_score(y_te, pred):.3f}")         # 両者の調和平均
```

```text
[[5848    2]
 [  97   53]]
適合率 0.964
再現率 0.353
F1     0.517
```

このモデルの正解率は 98.4% で、基準線の 97.5% をわずかに上回るだけだ。混同行列を見ると事情が分かる。陽性と言った 55 件はほぼ当たっている（適合率 96%）が、本物の陽性 150 件のうち 97 件を見逃している（再現率 35%）。

不正検知なら、このモデルは慎重すぎる。**見逃した 97 件がそのまま損失になる**からだ。どちらに寄せるべきかは、次の節で扱う閾値で調整できる。

> [!NOTE] 多クラス分類では平均の取り方を選ぶ
> 3 クラス以上では、クラスごとの指標を平均する。`average="macro"` はクラスを同じ重みで平均する（少数クラスも同じ重み）。`average="weighted"` は件数で重み付けする（多数クラスに引っ張られる）。少数クラスを見落としたくないなら macro を見る。

## 閾値を動かすと指標が入れ替わる：ROC-AUC と PR-AUC

多くの分類モデルは、直接「陽性/陰性」を出すのではなく、**陽性らしさの点数**（確率）を出す。`predict` は、その点数が 0.5 以上なら陽性とする。この 0.5 が**閾値**（しきいち）だ。

閾値を下げれば、陽性と判定する件数が増え、再現率は上がり、適合率は下がる。閾値を 1 つに決める前に「どの閾値でもどれくらい良いか」をまとめて測るのが、曲線の下の面積（AUC）の指標だ。

| 指標 | 縦軸 × 横軸 | 何も学ばないモデルの値 | 読み方 |
|---|---|---|---|
| ROC-AUC | 再現率 × 誤検知率（FP ÷ 全陰性） | 0.5 | ランダムに選んだ陽性 1 件と陰性 1 件で、陽性の方に高い点を付ける確率 |
| PR-AUC（平均適合率） | 適合率 × 再現率 | 正例の割合（ここでは 0.025） | 陽性らしい順に並べたとき、上位がどれだけ正例で埋まるか |

```python title="auc.py" caption="点数の並び順を評価する 2 つの AUC（confusion.py の続き）" {3,6}
from sklearn.metrics import roc_auc_score, average_precision_score  # 2 種類の AUC

score = model.predict_proba(X_te)[:, 1]  # ★ 陽性である確率（点数）を取り出す

print(f"ROC-AUC {roc_auc_score(y_te, score):.3f}")            # 基準は 0.5
print(f"PR-AUC  {average_precision_score(y_te, score):.3f}")  # ★ 基準は正例の割合
print(f"基準線  {y_te.mean():.3f}")  # 正例の割合 = 何も学ばないモデルの PR-AUC
```

```text
ROC-AUC 0.836
PR-AUC  0.592
基準線  0.025
```

2 つの数字は、**基準線が違うので直接比べられない**。ROC-AUC 0.836 は基準の 0.5 からの伸び、PR-AUC 0.592 は基準の 0.025 からの伸びとして読む。

### 「不均衡データなら PR-AUC」は常に正しいわけではない

実務の記事では「不均衡データでは ROC-AUC は楽観的すぎるので PR-AUC を使え」という助言がよく書かれる。一方で、McDermott らの NeurIPS 2024 の論文は、この主張は一般には成り立たないと示した。PR-AUC は正例の多い部分集団での改善を大きく評価しやすく、使い方によっては集団間の不公平を広げうる。論文は 150 万本以上の論文を調べ、この通説が出典なしで語られたり、元の主張を広げすぎて引用されたりしていることも報告している。

どちらを使うかは、データの偏りではなく**モデルの使われ方**で決めるのが筋がよい。

| モデルの使われ方 | 向く指標 |
|---|---|
| 点数の上位だけを人が確認する（上位 100 件を審査する、など） | PR-AUC、上位 k 件の適合率（precision@k） |
| 全体を並べ替える能力を比べたい。部分集団間で公平に比べたい | ROC-AUC |
| 最終的に 1 つの閾値で自動判定する | 閾値を決めたうえでの適合率・再現率、またはコスト（次節） |

## 誤りのコストから閾値を決める

閾値 0.5 には理由がない。確率の真ん中というだけで、あなたの業務のコストとは無関係だ。見逃し 1 件の損失が 10 万円、誤検知 1 件の確認コストが 5 千円なら、見逃しは誤検知の 20 倍高くつく。その比率で閾値を決めるべきだ。

scikit-learn 1.5 から入った `TunedThresholdClassifierCV` は、自分で決めた損得の関数を最も良くする閾値を、交差検証（データを入れ替えながら何度も評価する方法）で選ぶ。まず、閾値を手で変えたときの損失を見て、そのあと自動で選ばせる。

```python title="threshold.py" caption="見逃し 100・誤検知 5 のコストで閾値を選ぶ（auc.py の続き）" {6,13,16}
from sklearn.metrics import make_scorer  # 自作の関数を評価指標として登録する
from sklearn.model_selection import TunedThresholdClassifierCV  # 閾値を自動で選ぶ

def cost(y_true, y_pred):  # 予測の損失を計算する関数（単位は千円など何でもよい）
    tn, fp, fn, tp = confusion_matrix(y_true, y_pred, labels=[0, 1]).ravel()  # 4 マスを取り出す
    return fn * 100 + fp * 5  # ★ 見逃し 1 件 = 100、誤検知 1 件 = 5 の損失

for th in [0.5, 0.3, 0.1, 0.05]:  # 閾値を 4 通り試す
    pred = (score >= th).astype(int)  # 点数が閾値以上なら 1（陽性）
    print(f"閾値 {th:<4} 適合率 {precision_score(y_te, pred):.2f} "
          f"再現率 {recall_score(y_te, pred):.2f} 損失 {cost(y_te, pred):>6,}")

scorer = make_scorer(cost, greater_is_better=False)  # ★ 小さいほど良い指標として登録
tuned = TunedThresholdClassifierCV(LogisticRegression(max_iter=1000),  # 中身のモデル
                                   scoring=scorer, cv=5, random_state=0)  # 5 分割で評価
tuned.fit(X_tr, y_tr)  # ★ 学習用データだけで閾値を選ぶ（テスト用データは使わない）
print(f"選ばれた閾値 {tuned.best_threshold_:.3f}")
print(f"テストでの損失 {cost(y_te, tuned.predict(X_te)):,}")
```

```text
閾値 0.5  適合率 0.96 再現率 0.35 損失  9,710
閾値 0.3  適合率 0.85 再現率 0.48 損失  7,865
閾値 0.1  適合率 0.39 再現率 0.60 損失  6,690
閾値 0.05 適合率 0.18 再現率 0.69 損失  6,990
選ばれた閾値 0.091
テストでの損失 6,625
```

閾値を 0.5 から 0.1 付近に下げると、適合率は 96% から 39% に落ちるが、損失は 9,710 から 6,690 へ約 3 割減る。見逃しのほうがはるかに高くつくので、空振りを増やしてでも拾いにいく方が得になるわけだ。ただし 0.05 まで下げると、今度は誤検知のコストが効いて損失が増える。

`TunedThresholdClassifierCV` は学習用データだけを使って 0.091 を選び、テストでも損失 6,625 と手で探した最良の値に近い結果になった。閾値を**テスト用データを見ながら選ぶと、テストの点数が甘くなる**。選ぶのは学習用データ（か、別に取り分けた検証用データ）で行う。

> [!TIP] コストが分からないときは「1 日に確認できる件数」から決める
> 損失額を見積もれない現場は多い。その場合は、運用の制約から逆算する。「担当者が 1 日に確認できるのは 50 件」なら、上位 50 件に入る点数を閾値にし、その件数での再現率を報告する。

## 回帰の指標は外れ方の「罰し方」が違う

売上や需要のような数値を予測する回帰では、混同行列の代わりに**誤差の大きさ**を測る。代表的な 3 つは、同じ予測に対して違う順位を付けることがある。

| 指標 | 計算 | 特徴 | 向く場面 |
|---|---|---|---|
| MAE（平均絶対誤差） | 誤差の絶対値の平均 | 単位が元のまま。外れ値に引っ張られにくい | 「平均して何個ずれるか」を伝えたい |
| RMSE（二乗平均平方根誤差） | 誤差を二乗して平均し、平方根 | 大きな外れを強く罰する | 大外しが致命的（在庫切れ、発電量の過不足） |
| MAPE（平均絶対パーセント誤差） | 誤差 ÷ 実測値 の絶対値の平均 | 割合なので規模の違う商品を比べやすい | 規模の違う系列をまとめて評価したい。ただし実測値が 0 に近いと暴れる |

7 商品の需要を 2 通りの方法で予測した例で比べる。

```python title="regression_metrics.py" caption="同じ実測値に対する 2 つの予測を 3 つの指標で比べる" {5,7}
import numpy as np  # 数値計算のライブラリ
from sklearn.metrics import (mean_absolute_error, root_mean_squared_error,  # MAE と RMSE
                             mean_absolute_percentage_error)  # MAPE

actual = np.array([120, 80, 100, 3, 150, 90, 110])  # ★ 実際の需要。4 つ目は 3 個しか売れない商品
pred_a = np.array([110, 90, 95, 13, 140, 85, 105])  # 予測 A: どれも 5〜10 個ずれる
pred_b = np.array([118, 82, 101, 4, 90, 88, 112])   # ★ 予測 B: ほぼ正確だが 5 つ目を 60 個外す

for name, pred in [("予測A", pred_a), ("予測B", pred_b)]:  # 2 つの予測を順に評価する
    mae = mean_absolute_error(actual, pred)          # 平均して何個ずれたか
    rmse = root_mean_squared_error(actual, pred)     # 大外しを強く罰した誤差
    mape = mean_absolute_percentage_error(actual, pred)  # 実測値に対する割合の誤差
    print(f"{name}  MAE {mae:5.1f}  RMSE {rmse:5.1f}  MAPE {mape:6.1%}")
```

```text
予測A  MAE   7.9  RMSE   8.2  MAPE  53.7%
予測B  MAE  10.0  RMSE  22.7  MAPE  11.8%
```

MAE と RMSE では予測 A が良く、MAPE では予測 B が良い。予測 B は 1 商品で 60 個外しており、RMSE はその大外しを強く罰する。一方の予測 A は、3 個しか売れない商品を 13 個と予測した。10 個のずれでも割合では 333% になり、MAPE を押し上げた。

どちらが正しいかは業務で決まる。大量の在庫切れが一番困るなら RMSE、少量品の割合の誤差を気にしないなら MAPE は使わない、という具合だ。実測値に 0 が含まれるなら、MAPE は計算できない（0 で割る）ので最初から候補から外す。

## 活用事例：指標の選び方は業界で決まる

指標の選び方には、分野ごとにある程度の定石がある。次の表は、誤りのコストの非対称さから整理したものだ。

| 分野 | 課題 | 重視する指標 | 理由 |
|---|---|---|---|
| 金融 | クレジットカードの不正検知 | 再現率、上位 k 件の適合率、損失額 | 見逃しは直接の損失。確認できる件数に上限がある |
| 医療 | がん・感染症のスクリーニング | 再現率（感度）、特異度 | 見逃しは命に関わる。二次検査で誤検知を拾い直せる |
| メール | スパム判定 | 適合率 | 大事なメールをスパム扱いにするほうが困る |
| 製造 | 外観検査の不良品検出 | 再現率、誤検知率 | 不良の流出は信用問題。誤検知は目視で再確認 |
| 小売 | 需要予測 | RMSE、または過小予測を重く罰する損失 | 欠品（機会損失）と過剰在庫（廃棄）のコストが違う |
| 検索・推薦 | 上位に並べる商品の選択 | NDCG、precision@k | ユーザーが見るのは上位の数件だけ |

> [!NOTE] 医療の「感度・特異度」
> 医療では再現率を**感度**、陰性を正しく陰性と判定する割合 TN ÷ (TN + FP) を**特異度**と呼ぶ。同じ概念の別名なので、論文を読むときは対応表を頭に置いておくとよい。

## 指標を選ぶ 5 つの問い

指標を決めるときは、次の問いに順に答える。答えが決まれば、指標はほぼ自動的に決まる。

| # | 問い | 答えと選ぶもの |
|---|---|---|
| 1 | 予測するのはカテゴリーか数値か | カテゴリー → 混同行列系、数値 → MAE・RMSE・MAPE |
| 2 | 正例は全体の何 % か | 数 % 以下なら正解率を捨て、何も学ばないモデルの点数を基準線にする |
| 3 | 見逃しと誤検知のどちらが高くつくか | 見逃し → 再現率、誤検知 → 適合率、同程度 → F1 |
| 4 | 最終的に閾値で自動判定するか、上位を人が見るか | 自動判定 → コストで閾値を決める、人が見る → precision@k・PR-AUC |
| 5 | 部分集団（地域・年齢層など）ごとの差が問題になるか | 問題になる → 集団ごとに同じ指標を並べる。PR-AUC だけで比べない |

## 評価指標のチェックリスト

| 確かめること | 対応する節 |
|---|---|
| 何も学ばないモデルの点数を基準線として測った | 正解率の落とし穴 |
| 正解率だけでなく、混同行列を見た | 混同行列 |
| 見逃しと誤検知のコストを比べ、重視する指標を決めた | 混同行列、活用事例 |
| AUC を読むとき、基準線（0.5 か正例の割合か）を意識した | ROC-AUC と PR-AUC |
| 閾値を 0.5 のまま使わず、学習用データでコストから選んだ | 閾値を決める |
| 回帰では、大外しと割合のどちらを重視するかで指標を選んだ | 回帰の指標 |

評価指標は「モデルの成績表」ではなく「業務の損得を数字にしたもの」だ。実務の記事でも、指標をデータサイエンティストだけで決めず、事業側と KPI（事業の目標値）とのつながりを確かめながら設計すべきだと指摘されている。これが決まって初めて、モデルの改善が本当の改善かどうかを判断できる。

次回「[訓練データで満点のモデルが本番で外れる](2026-09-30-ml-basics-2-overfitting.html)」では、学習用データの点数とテスト用データの点数がずれる**過学習**を扱う。今回テスト用データを分けておいた理由も、そこではっきりする。
