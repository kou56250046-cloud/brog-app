# 記事の見出し画像（設計図ヒーロー） — 要件

規模: M（新しい記法 ```` ```hero ```` と新モジュールを足し、flow の解析器を拡張する。
触るファイルは 8 つ以上、既存の記事 33 本にも図を書く）

改訂: 2026-10-06 第 2 版。第 1 版（前付けの `hero:` で flow / steps / layers / compare の 4 型を描く）は、
実装途中でユーザーが方針を変えた。4 型は「要点の並び」は示せるが、記事の構造や設計の考え方までは伝わらない。
本文の ```` ```flow ```` 図が分かりやすいという評価を受けて、それを見出し用に強化した「設計図」に切り替える。

## 背景

記事ページの冒頭はタイトル・説明文・メタ情報の文字だけで、記事が扱う仕組みの全体像（何がどこを流れ、誰が何を決めるか）と、
その設計の考え方（なぜそう分けるか）が一目では分からない。記事一覧も文字の行が並ぶだけで、記事の区別が付きにくい。

各記事の冒頭に、全体フロー・アーキテクチャ図の形の見出し画像（設計図ヒーロー）を大きく置く。
依存ゼロ・相対パス・オフライン動作の制約を守るため、ビルド時にインライン SVG を生成する。

- 「この記事で分かること」（TIP コールアウト）と内容が重なってよい（2026-10-06 ユーザー確認）
- SNS 連携（OGP 画像）は使う予定がない（同日ユーザー確認）
- 見出し画像が大きくなってよい（同日ユーザー確認）

## 受入条件

### 記法

- [ ] 本文中に次の ```` ```hero ```` ブロックを 1 つ書くと、ビルドがそれを記事の見出し画像にする。ブロックは本文からは取り除かれ、
      本文の HTML・検索インデックス・読了時間の計算に入らない
  ````markdown
  ```hero
  title 固定できる所は固定し、判断が要る所だけエージェントに任せる
  group wf Workflow（コードが決める）
    A[受付] --> B[分類]
    F[報告]
  end
  group ag エージェント（LLM が決める）
    C(調査):::llm <--> D[ツール]
  end
  B --> C
  C -->|結論| F
  note C 回数・費用・時間の上限と承認待ちを 1 か所で守る
  note F 結論は根拠と突き合わせてから報告に回す
  ```
  ````
- [ ] ノード・矢印の書き方は ```` ```flow ```` と同じ（`[]` `()` `{}` `([])`、`-->` `-.->` `==>`、ラベル付き矢印、`:::hl` `:::muted`）。
      加えて次が使える
  | 記法 | 意味 |
  |---|---|
  | `title 文` | 図の大見出し（必須、1 つ） |
  | `group ID 名前` 〜 `end` | レーン（責任・層・境界）。中で初めて定義したノードがそのレーンに入る。ネストしない |
  | `:::code` `:::llm` `:::human` `:::data` | 担い手（コード / LLM / 人 / データ）。色と凡例で区別する |
  | `:::llm:::hl` | 担い手と強調（`hl` / `muted`）は 2 つまで並べられる。枠の色は担い手、太さ・破線は `hl` / `muted` が決める |
  | `<-->` | 双方向の矢印 |
  | `note ノードID 文` | 設計の要点。ノードに番号（1, 2, 3）を付け、図の下に番号つきで並べる。1 ノードに 1 つまで |
- [ ] 次のどれかに当たるとビルドが `<slug>.md: hero …（理由）` の警告を出し、その記事はフォールバック画像になる。ビルドは止まらない
  - `title` が無い、または全角換算 40 字を超える
  - ノードが 2 個未満または 12 個を超える。レーンが 4 つ以上（group に入らないノードの無名レーンも 1 つと数える）。`group` の入れ子や `end` の不足
  - ノードのラベルが、全角 8 字幅（120px・15px 換算）で折り返して 3 行以上になる
  - 未知のクラス（`hl` `muted` `code` `llm` `human` `data` 以外）、担い手を 2 つ付けた、クラスを 3 つ以上付けた
  - `note` が 4 つ以上、存在しないノードを指す、同じノードに 2 つ、1 つが全角換算 40 字を超える
  - 横向き（下記）の図の幅が 1008 を超える（ラベルが全角 8 字なら段は 5 つまでが目安）
  - ```` ```hero ```` ブロックが 2 つ以上ある
- [ ] 公開記事に ```` ```hero ```` が無いときも `<slug>.md: hero がありません（フォールバック画像になります）` の警告を出す
- [ ] ```` ```flow ```` の既存の 67 図の出力が変更前と 1 文字も変わらない。```` ```flow ```` の中で `group` `note` `title` を書くとビルドが例外で止まる
      （flow は今までどおり group を描けないので、黙って捨てない）

### 記事ページの表示

- [ ] `.post-head` の `.spec`（公開日などの表）の直後に `<figure class="hero">` が出る。上から順に
      大見出し（HTML のテキスト）、図（インライン SVG）、凡例（使った担い手だけ）、設計の要点（番号つきリスト）
- [ ] 図の中でレーンは帯（名前つき）として描かれ、同じレーンのノードは帯の中に並ぶ。
      横向きでは、ノードの左右の位置は flow と同じく矢印の段で決まる。
      縦向きでは、レーンの帯を上から順に積み、帯の中のノードを段の順に 1 列で並べる。レーンをまたぐ矢印と戻る矢印は図の右側の通り道を回す
- [ ] 担い手ごとに枠と薄い面の色が違い、凡例の色見本と一致する。ノードの文字は `--ink` で、色の面の上でも読める
- [ ] `note` を付けたノードの右上に番号の丸が付き、図の下のリストの番号と一致する
- [ ] ビューポートが 860px 以上なら横向き（段が左→右、レーンが上下に並ぶ）、860px 未満なら縦向き（レーンを上から積む）の図を出す。
      もう一方は `display: none`
- [ ] 図は自然な大きさより拡大せず、入れ物（`.spec` と同じ最大幅）より広ければ縮める。ページに横スクロールが出ない
- [ ] 幅 360 / 375 / 860 / 1366 / 1920px で、ノードの文字の表示サイズが 11px 以上、それ以外の図の中の文字（レーン名・矢印ラベル・番号）が 9px 以上
      （`getBoundingClientRect` と viewBox の比で測る）
- [ ] ライト・ダーク・手動切替（`data-theme`）のどれでも、SVG 内に色の直書き（`#`・`rgb(`）が無く、すべて CSS 変数で塗られている
- [ ] SVG 内に `id` 属性が無い（矢印の先は `<marker>` を使わずに描く）
- [ ] 図の SVG は `role="img"` と、大見出し・ノード・要点をつないだ `aria-label` を持つ
- [ ] ```` ```hero ```` が無い・不正な記事は、slug から決まる幾何学模様にカテゴリー名・シリーズ名を添えたフォールバック画像になる（`aria-hidden`）

## 非目標

- OGP・SNS 用の画像（PNG 変換、`og:image`）は作らない。画像ファイルとして書き出さない
- 手描き SVG・イラスト・写真・外部サービス（Canva など）の画像は使わない
- `group` の入れ子、レーンをまたぐ自由配置、ノードの手動座標指定はしない
- 矢印が他のノードを避ける経路探索はしない（flow と同じ段組みの範囲で描く）
- アニメーション・ホバーで要点を光らせるなどの操作はしない
- 本文の ```` ```flow ```` 図に group・担い手・note を使えるようにはしない
- 幅 360px 未満の画面での文字サイズは保証しない（崩れずに縮むことだけを守る）
- 前付けでの指定（第 1 版の `hero:`）は残さない。前付けパーサは変更前に戻す
- 記事ごとの色指定、カテゴリー色のダーク用の別色は作らない
- RSS・サイトマップ・検索インデックスに hero を入れない
- 「この記事で分かること」コールアウトの内容は変えない

## 制約

- npm 依存ゼロ。Node 標準モジュールだけで生成する。CDN フォントを読み込まない
- 生成 HTML のリンク・参照は相対パス（SVG 内には URL を入れない）
- PWA のプリキャッシュとオフライン表示はそのまま動く（インライン SVG なので `sw.js` は変えない）
- 日本語の文字幅は flow と同じ概算（全角 1em・半角 0.58em）で見積もる
