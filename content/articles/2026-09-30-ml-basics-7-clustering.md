「顧客をいくつかのタイプに分けて、それぞれに合った施策を打ちたい」。こうした依頼で使われるのが**クラスタリング**だ。正解ラベルのないデータを、似たもの同士のグループ（クラスタ）に自動で分ける。

ここまでの教師あり学習と決定的に違うのは、**正解がないので、正解率で良し悪しを測れない**ことだ。どの手法でも、とりあえず何らかのグループ分けは出てくる。それが意味のある区切りなのか、手法の癖が作った幻なのかを見極める手順が要る。この記事では、その手順を中心に整理する。

> [!TIP] この記事で分かること
> - k-means の仕組みと、標準化しないと結果が壊れる理由
> - エルボー法とシルエット係数によるクラスタ数の決め方
> - 月形や雑音の混ざったデータで、k-means・階層型・DBSCAN・HDBSCAN がどう振る舞うか
> - クラスタの結果を「事業の言葉」に翻訳する方法
> - 手法を選ぶ判断軸と、新しいデータを割り当てられる手法・られない手法の違い

## k-means：中心に近いもの同士をまとめる

最もよく使われる **k-means** は、次の 2 手を繰り返すだけの単純な方法だ。

1. k 個の「中心」を置き、各データを最も近い中心のグループに入れる
2. 各グループの平均の位置に、中心を動かす

中心が動かなくなったら終了だ。クラスタ数 k は人が事前に決める。「近さ」は、各項目の差の二乗を足した距離（ユークリッド距離）で測る。

この「距離で測る」ことが、最初の落とし穴になる。年間購入額（円）と来店回数（回）で顧客を分ける例で確かめる。データは、「たまに来て少し買う人」「よく来て少しずつ買う常連」「たまに来て高額を買う人」の 3 グループから作った。

```python title="customers.py" caption="標準化しないと、単位の大きい列だけで分けてしまう" {14}
import numpy as np  # 数値計算のライブラリ
from sklearn.cluster import KMeans  # k-means
from sklearn.preprocessing import StandardScaler  # 各列を平均 0・ばらつき 1 に揃える
from sklearn.metrics import adjusted_rand_score  # 本当のグループとの一致度（1 が完全一致）

rng = np.random.default_rng(0)  # 乱数の発生器
g1 = np.column_stack([rng.normal(30000, 8000, 300), rng.normal(2, 1, 300)])  # たまに・少額
g2 = np.column_stack([rng.normal(40000, 8000, 200), rng.normal(20, 3, 200)])  # 常連・少額
g3 = np.column_stack([rng.normal(250000, 40000, 60), rng.normal(6, 2, 60)])  # たまに・高額
X = np.vstack([g1, g2, g3])  # 560 人分を 1 つの表にする（列: 購入額, 来店回数）
X[:, 1] = np.clip(X[:, 1], 0, None)  # 来店回数がマイナスにならないようにする
truth = np.repeat([0, 1, 2], [300, 200, 60])  # 答え合わせ用の本当のグループ

for name, data in [("そのまま", X), ("標準化", StandardScaler().fit_transform(X))]:  # ★
    labels = KMeans(3, n_init=10, random_state=0).fit_predict(data)  # 3 つに分ける
    print(f"{name:<5} 一致度 {adjusted_rand_score(truth, labels):.2f}")
```

```text
そのまま  一致度 0.28
標準化   一致度 1.00
```

そのままでは一致度 0.28 で、ほとんど分けられていない。購入額は数万〜数十万の幅で動き、来店回数は数回〜20 回しか動かない。距離はほぼ購入額の差だけで決まり、「常連かどうか」という来店回数の違いが無視されたのだ。標準化して列の尺度を揃えると、一致度は 1.00 になり、3 グループを正しく分けられた。

> [!WARNING] 距離を使う手法の前には、必ず尺度を揃える
> k-means・階層型・DBSCAN など、距離を使う手法はすべて同じ問題を抱える。標準化（`StandardScaler`）のほか、金額のように偏った分布の列は、対数を取ってから標準化すると外れ値に振り回されにくい。

## クラスタ数 k はどう決めるか

k-means では k を人が決める。決め方の目安として、2 つの指標がよく使われる。

| 指標 | 計算 | 読み方 |
|---|---|---|
| 慣性（inertia） | 各データと、所属する中心との距離の二乗の合計 | k を増やすと必ず下がる。下がり方が急に緩やかになる「ひじ」の k を選ぶ（エルボー法） |
| シルエット係数 | 自分のクラスタ内の近さと、隣のクラスタとの離れ具合を比べた値 | −1〜1。大きいほど、よくまとまり、よく離れている |

```python title="choose_k.py" caption="k を 2〜7 に変えて、慣性とシルエット係数を見る（customers.py の続き）" {6,7}
from sklearn.metrics import silhouette_score  # シルエット係数

Xs = StandardScaler().fit_transform(X)  # 標準化したデータを使う
for k in range(2, 8):  # k = 2, 3, …, 7 を試す
    km = KMeans(k, n_init=10, random_state=0).fit(Xs)  # k 個に分ける
    sil = silhouette_score(Xs, km.labels_)  # ★ まとまり具合と離れ具合
    print(f"k={k}  慣性 {km.inertia_:6.1f}  シルエット {sil:.3f}")  # ★ 慣性は k とともに必ず下がる
```

```text
k=2  慣性  580.6  シルエット 0.668
k=3  慣性   53.4  シルエット 0.852
k=4  慣性   41.9  シルエット 0.818
k=5  慣性   30.7  シルエット 0.671
k=6  慣性   26.6  シルエット 0.669
k=7  慣性   22.7  シルエット 0.655
```

慣性は k = 2 から 3 で 580 から 53 へ激減し、その後はゆっくりとしか下がらない。ひじは k = 3 だ。シルエット係数も k = 3 で最大の 0.852 になり、2 つの指標が同じ答えを示している。

実際のデータでは、こうきれいに決まることは少ない。指標は候補を 2〜3 個に絞るために使い、最後は**次の節の「事業の言葉で説明できるか」**で決める。

> [!NOTE] k は「施策の数」でもある
> 指標上は k = 8 が最良でも、マーケティングの担当者が 8 種類の施策を用意できないなら、その区切りは使われない。k を決めるときは、運用できる数の上限も条件に入れる。

## 結果を事業の言葉に翻訳する

クラスタリングの結果は「クラスタ 0、1、2」という番号でしかない。番号のままでは誰も使えないので、**各クラスタの平均的な姿を要約して、名前を付ける**。この作業こそが、クラスタリングで最も価値のある部分だ。

```python title="profile.py" caption="クラスタごとの人数と平均を、元の単位で要約する（choose_k.py の続き）" {3}
km = KMeans(3, n_init=10, random_state=0).fit(Xs)  # 決めた k = 3 で分ける
for c in range(3):  # クラスタごとに
    members = X[km.labels_ == c]  # ★ 標準化前の元のデータで要約する（円・回のまま読める）
    print(f"クラスタ {c}  人数 {len(members):>3}  "
          f"購入額 {members[:, 0].mean():>9,.0f} 円  来店 {members[:, 1].mean():5.1f} 回")
```

```text
クラスタ 0  人数 200  購入額    39,707 円  来店  19.6 回
クラスタ 1  人数 301  購入額    30,020 円  来店   2.0 回
クラスタ 2  人数  59  購入額   251,015 円  来店   6.3 回
```

この表から、次のような名前と施策の案が作れる。

| クラスタ | 名前 | 施策の案 |
|---|---|---|
| 0 | よく来る常連（少額） | 1 回あたりの購入額を上げる。まとめ買いの提案 |
| 1 | たまに来る一般客 | 来店の頻度を上げる。再来店のクーポン |
| 2 | 少数の高額客 | 離反させない。専用の案内や優先対応 |

名前を付けられないクラスタや、施策が思いつかないクラスタがあれば、それは区切り方が事業に合っていないサインだ。特徴量や k を見直す。

> [!TIP] 小売の定番は RFM
> 顧客のクラスタリングでは、最終購入からの日数（Recency）、購入回数（Frequency）、購入金額（Monetary）の 3 つを特徴量にする **RFM 分析**がよく使われる。まずこの 3 列から始め、必要に応じて商品カテゴリーの比率などを足すと、結果に名前を付けやすい。

## 形と雑音で手法を選ぶ：k-means・階層型・DBSCAN・HDBSCAN

k-means は「各クラスタが中心の周りに丸く集まっている」ことを前提にしている。scikit-learn の公式ドキュメントも、k-means の慣性は丸く凸な形を前提にしており、細長い形や不規則な形には弱いと注意している。実際のデータには、細長いグループや、どこにも属さない雑音も混ざる。

主な手法の考え方は次の通りだ。

| 手法 | 考え方 | 決めるもの | 雑音の扱い |
|---|---|---|---|
| k-means | 中心からの距離でまとめる | クラスタ数 k | どこかのクラスタに必ず入れる |
| 階層型（凝集型） | 近いもの同士を 1 つずつ合体させ、系統樹（デンドログラム）を作る | クラスタ数、または切る高さ | 必ず入れる |
| DBSCAN | 密集している点を連鎖的につなぐ。まばらな点は雑音にする | 近傍の半径 `eps`、最小の点数 | 雑音（−1）として外す |
| HDBSCAN | DBSCAN を半径を変えながら実行し、安定なクラスタを選ぶ。密度の違うクラスタにも対応 | 最小のクラスタの大きさ | 雑音として外す |

HDBSCAN は、scikit-learn 1.3 で本体に取り込まれた。月形に並んだ 2 つのグループに、雑音を 25 点混ぜたデータで比べる。

```python title="shapes.py" caption="月形 2 つ＋雑音のデータで、4 つの手法を比べる（profile.py の続き）" {5,10}
from sklearn.datasets import make_moons  # 月形のデータを作る
from sklearn.cluster import AgglomerativeClustering, DBSCAN, HDBSCAN  # 階層型・密度ベースの手法

Xm, ym = make_moons(500, noise=0.07, random_state=0)  # 月形 2 つ（500 点）
Xm = np.vstack([Xm, rng.uniform(-1.5, 2.5, (25, 2))])  # ★ どこにも属さない雑音を 25 点足す
ym = np.concatenate([ym, -np.ones(25, dtype=int)])  # 雑音の正解ラベルは −1

models = [("k-means", KMeans(2, n_init=10, random_state=0)),
          ("階層型", AgglomerativeClustering(2)),
          ("DBSCAN", DBSCAN(eps=0.2, min_samples=5)),  # ★ 半径 0.2 以内に 5 点あれば「密集」
          ("HDBSCAN", HDBSCAN(min_cluster_size=20, copy=True))]  # 20 点以上をクラスタとみなす
for name, model in models:
    labels = model.fit_predict(Xm)  # 各点のクラスタ番号（雑音は −1）
    ari = adjusted_rand_score(ym[ym >= 0], labels[ym >= 0])  # 月形の点だけで一致度を測る
    print(f"{name:<8} 一致度 {ari:.2f}  雑音と判定 {np.sum(labels == -1):>2} 点")
```

```text
k-means  一致度 0.25  雑音と判定  0 点
階層型   一致度 0.42  雑音と判定  0 点
DBSCAN   一致度 1.00  雑音と判定 16 点
HDBSCAN  一致度 0.98  雑音と判定 22 点
```

k-means（0.25）と階層型（0.42）は、月形を直線で切るように分けてしまい、雑音も必ずどこかに入れる。密集した点をつないでいく DBSCAN と HDBSCAN は、月形をほぼ完全に分け、雑音も外した。

DBSCAN は半径 `eps` の値に敏感で、データの密度が場所によって違うとうまくいかない。HDBSCAN は半径を決めなくてよく、「最小のクラスタの大きさ」のような直感的な設定で済む。**形が分からないデータでは、まず HDBSCAN を試す**のが扱いやすい。

> [!IMPORTANT] DBSCAN・HDBSCAN は新しいデータを割り当てられない
> k-means は学習後に `predict` で新しい顧客をどのクラスタかに割り当てられる。一方、scikit-learn の DBSCAN・HDBSCAN・階層型は、学習に使ったデータにしか番号を付けられない（`predict` がない）。毎日新しい顧客を振り分ける運用なら、k-means を使うか、クラスタ番号を正解として分類モデルを別に学習させる。

## 活用事例：クラスタリングが使われる場面

| 分野 | 使い方 | よく使われる手法 |
|---|---|---|
| 小売・EC | 購買行動（RFM など）で顧客を分け、施策を変える | k-means（新規顧客を割り当てやすい） |
| セキュリティ・運用 | アクセスログやエラーを分け、どこにも属さない点を異常として調べる | DBSCAN・HDBSCAN（雑音を外せる） |
| 文書・問い合わせ | 文章を埋め込みベクトルにし、話題ごとにまとめる | 次元削減＋HDBSCAN。話題抽出ライブラリ BERTopic の既定の構成も UMAP＋HDBSCAN |
| 生命科学 | 遺伝子の発現パターンから細胞の種類を分ける | グラフベースの手法、階層型 |
| 物流・店舗 | 配送先や店舗の位置をまとめ、拠点の候補を決める | k-means（中心が拠点の候補になる） |

## クラスタリングの手法を選ぶ

```flow caption="クラスタリングの手法の選び方"
A([尺度を揃えたデータ]) --> B{新しいデータを\n割り当てる?}
B -- はい --> C([k-means]):::hl
B -- いいえ --> D{雑音・外れ値を\n外したい?}
D -- はい --> E([HDBSCAN])
D -- いいえ --> F{グループの階層\nを見たい?}
F -- はい --> G([階層型])
F -- いいえ --> H([k-means と\nHDBSCAN を比べる])
```

| 観点 | k-means | 階層型 | HDBSCAN |
|---|---|---|---|
| クラスタの形 | 丸く、大きさが揃っている | 設定しだい（ward なら丸寄り） | 任意の形、大きさや密度が違ってもよい |
| 決める設定 | クラスタ数 | クラスタ数か切る高さ | 最小のクラスタの大きさ |
| 雑音 | すべてどこかに入れる | すべてどこかに入れる | 雑音として外す |
| 件数 | 非常に多くても速い（MiniBatch 版もある） | 数万件程度まで | 大量でも使える |
| 新しいデータ | `predict` で割り当てられる | 割り当てられない | 割り当てられない |
| 結果の説明 | 中心の値で説明しやすい | 系統樹で関係を見せられる | 形が自由な分、説明に工夫が要る |

## クラスタリングのチェックリスト

| 確かめること | 対応する節 |
|---|---|
| 距離を使う前に、各列の尺度を揃えた | k-means |
| k をエルボー法・シルエット係数で絞り、運用できる数かも確かめた | クラスタ数 |
| 乱数の種を変えて学習し直し、同じ区切りが出るか確かめた | クラスタ数 |
| 各クラスタを元の単位で要約し、名前と施策を付けられた | 事業の言葉に翻訳 |
| 形や雑音に合わせて手法を選んだ | 形と雑音で選ぶ |
| 新しいデータを割り当てる必要があるか確かめた | 形と雑音で選ぶ |

クラスタリングに正解はない。だからこそ、「その区切りで何をするか」を先に決めておくことが、良い結果を得る最短の道になる。
